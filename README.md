# Agenda Clínica

Sistema web de gestión de turnos y agenda para una clínica pequeña.

> Proyecto personal de aprendizaje desarrollado en PHP puro.

## ¿Por qué existe este proyecto?

Este proyecto nació como una forma práctica de aprender programación y desarrollo web construyendo una aplicación realista.

La idea no es comenzar intentando crear un sistema empresarial complejo, sino desarrollar progresivamente una herramienta útil mientras se incorporan nuevos conocimientos.

El proyecto prioriza:

- Aprendizaje práctico.
- Código comprensible.
- Soluciones simples.
- Evolución progresiva.
- Funcionalidad antes que complejidad.

---

## Objetivo

Crear una herramienta sencilla para administrar la agenda y los turnos de una clínica pequeña.

El proyecto se desarrollará por etapas, incorporando funcionalidades a medida que sean necesarias y que aporten valor real.

## Filosofía del proyecto

Este proyecto no busca incorporar complejidad por el simple hecho de utilizar patrones o tecnologías modernas.

Las decisiones técnicas deben responder a una necesidad concreta.

Se prioriza:

1. Comprender el problema.
2. Implementar una solución sencilla.
3. Mantener el código legible.
4. Aprender durante el proceso.
5. Refactorizar cuando exista una razón real.
6. Incorporar complejidad únicamente cuando sea necesaria.

## Fuera de alcance por ahora

Para evitar complejidad prematura, actualmente quedan fuera de alcance:

- Sistema avanzado de permisos.
- Multiusuario.
- Arquitecturas empresariales.
- Microservicios.
- Integraciones externas innecesarias.
- Automatizaciones complejas.
- Funcionalidades que no aporten valor a una clínica pequeña.

Esto puede cambiar en el futuro si el proyecto lo necesita.

## Próximos pasos

El próximo paso no es agregar más funcionalidades.

Primero se realizará una auditoría completa del código existente.

A partir de esa auditoría se definirá:

1. Qué funciona correctamente.
2. Qué debería corregirse.
3. Qué debería refactorizarse.
4. Qué funcionalidades faltan.
5. Qué funcionalidades realmente valen la pena.
6. Qué debería hacerse primero.
7. Qué debería dejarse para más adelante.

El roadmap se actualizará después de cada etapa importante.

---

## Objetivo final

Construir una aplicación funcional mientras se aprende programación de forma práctica y progresiva.

La calidad del proyecto no se medirá solamente por la cantidad de funcionalidades, sino también por cuánto se comprende de lo que se está construyendo.
